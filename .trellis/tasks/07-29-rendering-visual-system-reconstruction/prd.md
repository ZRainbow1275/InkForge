# 全类型渲染视觉系统重制

> 状态：`in_progress`
> 工作方式：`$grill-me`
> 当前阶段：微信七套视觉方向已用本机一篇真实短文生成临时 contact sheet 并完成本会话目检；因证据包含操作者数据且未归档为脱敏 manifest，独立可审计视觉验收仍开放。XHS/知乎七 Variant 原生重排、canonical UI 持久化和外部平台证据也仍为开放门禁；当前优先交付微信渲染给操作者实测。

## Goal

恢复 InkForge 最初的渲染设计架构：

> 建立一套原子化设计系统（Atomic Design System）作为共同底座，通过 7 种视觉变体（Variants）覆盖 10 类文章，再由微信、小红书、知乎各自的平台适配器生成真实产物。

本轮不为当前 24 个运行时预设分别复制 24 套 CSS。24 个入口需要保留，但它们是兼容 ID、平台展示配置或高级能力入口；视觉系统的权威结构是：

```text
InkForge 品牌 DNA
  +
内容语义
  -> 原子底座
  -> 7 个视觉变体
  -> 10 类文章配置
  -> 平台适配器
  -> 微信 HTML/SVG | 小红书图片页/文本 | 知乎 Markdown/图片
```

最终目标是：七个变体各自惊艳且可辨，十类文章都得到专门服务，完整正文从开篇到文末都被设计；同时只维护一套可组合、可测试、可扩展的底座。

GPT Image 2 用于七个变体的概念板、完整长页构图参考和视觉批评板；最终输出必须由 InkForge 的确定性 HTML、CSS、SVG、Markdown 和图片渲染器实现，并在原生 Tauri 软件中真实验收。

## Recovered Architecture

### Layer 0: InkForge Brand DNA

每套必须出现但不得压平差异的少数不变量：

- 正式墨滴 · 笔锋 · 铁砧标志只在报头或 colophon 克制出现；
- Graphite / Vellum 承担阅读底色，Kiln 火种作为稀缺品牌信号；
- Tempera 与 Amber 分别承担冷却呼吸与锻线 / 强调；
- 宋 / 黑 / Mono 的角色纪律、装裱工艺和“温暖的精确”保持一致；
- 品牌身份固定，版式骨架、信息流、组件外形和领域母题不固定。

### Layer 1: Design Tokens

只定义可复用的视觉事实，不携带文章类型：

- CJK / Latin / Mono 字体角色；
- 字号阶梯；
- 行高、字距、段距、版心；
- 纸张、墨色、强调色、中性色、状态色；
- 线宽、边框、圆角、阴影；
- 空间尺度；
- 动效持续时间和降级；
- 微信安全 SVG 几何参数；
- 深色模式与对比度规则。

### Layer 2: Atoms

最小视觉原子：

- 文本角色；
- 线、点、方格、菱形、印章、编号；
- 图标 path；
- 色带、底纹、纸张块；
- 图片框、题注标记；
- 代码语言标记；
- 引用号、来源号、脚注号；
- 链接状态；
- 进度和数据单位。

原子不得直接绑定 `thesis`、`legal` 等 preset ID。

### Layer 3: Molecules

原子组合成可重用组件：

- 报头；
- kicker；
- 标题组；
- 作者 / 日期 / 来源 / 阅读时间元数据行；
- H2–H6 标题；
- 引用与来源；
- 数据统计卡；
- 时间线节点；
- 对比项；
- 图框与题注；
- 代码标题栏；
- 公式 / Mermaid 容器；
- 歌曲、名片、文章链接、媒体卡；
- CC 协议条；
- 结束标。

### Layer 4: Organisms

面向文章阅读流程的结构：

- 开篇系统；
- 摘要 / 导语系统；
- 目录与长文导航；
- 章节系统；
- 论证系统；
- 数据与图表系统；
- 图片与图集系统；
- 引用与参考资料系统；
- 富媒体系统；
- 文末版权页。

### Layer 5: Seven Variants

变体只负责“如何编排和表达”，不复制组件实现：

- 字体角色映射；
- 色彩角色映射；
- 空间节奏；
- 信息密度；
- 标题和报头构图；
- 组件选择与强度；
- 母题组合；
- 图片策略；
- 动效许可；
- 平台降级策略。

### Layer 6: Ten Article Profiles

文章类型配置选择一个主 Variant，再追加内容领域能力：

- 法条 / 案例 / 时间线；
- 研报 KPI / 表格 /结论；
- 新闻事实 / 来源 / 时间；
- AIGC 图片 / 视频 / prompt；
- 编程代码 / 版本 / 终端；
- 学习标签 / 知识关联；
- 整活梗图；
- 人生感悟的极简强度；
- 论文脚注 / 参考文献 / Mermaid。

同一 Variant 可以覆盖多个文章类型，但通过文章 Profile 决定组件组合和语义，不通过复制 CSS 实现。

### Layer 7: Platform Adapters

- 微信：真实 inline HTML 承载可重排文字；安全 SVG 承载几何、短标签和经过证据允许的动效。
- 小红书：生成真实图片页 / 轮播 / 长图与平台文案，不复用微信 HTML。
- 知乎：生成语义 Markdown / HTML 和真实图片 fallback，不复用微信 wrapper。

## Requirements

### R1. 一个底座，不得复制七套组件

- 组件语义、输入校验、安全规则和平台 fallback 只实现一次。
- Variant 通过 token、配方、槽位和强度参数组合。
- 禁止为每个 preset 复制一整套独立 renderer。

### R2. 七变体必须真正不同

每个 Variant 至少在以下七项中形成五项独占组合：

- 报头构图；
- 字体角色；
- 版心与节奏；
- 标题层级；
- 图像处理；
- 数据 / 引用 / 列表处理；
- 几何母题；
- 色彩质量；
- 文末结构；
- 动效逻辑。

任意两个 Variant 不得只换颜色。

### R3. 10 类文章全部有明确映射

- 每类文章有一个默认 Variant；
- 可以由用户换 Variant；
- Article Profile 决定领域组件；
- Variant 决定视觉编排；
- Platform Adapter 决定最终产物；
- 三者不得揉成同一 preset ID。

### R4. 正文优先

- 设计必须覆盖正文 70%–90% 的阅读面积。
- 封面、SVG、H2 和文末卡不能成为唯一视觉差异。
- 长文需要标题路标、章节节奏、强调密度预算和休息点。
- 默认移动端基准尊重 14px / 至少 22 字每行的原始要求，并允许 Typography 调整；不再强制用过宽留白制造“高级感”。

### R5. GPT Image 2 工作流

1. 共同底座使用三份可比较概念方向确定视觉坐标；
2. 七个 Variant 按 D13 批量生成、批量剔除同质化和不可落地方向；
3. 每套保留一份最终长文方向板，并拆解为原子、组件、正文节奏与平台 fallback；
4. 用确定性 HTML、CSS、SVG、Markdown 和图片渲染实现；
5. 把真实 Tauri 软件截图交给 GPT Image 2 做偏差批评；
6. 修订后以真实软件、微信复制读回和三平台本地产物为准。

生成图不是完成证据，也不能替代可编辑文字。

#### V4 生成前微信安全原语预算

允许：

- 普通语义标签、真实 DOM 装饰节点、inline style；

Xiumi Animation Style Picker Icon Residue - 2026-06-28

Scope:
- Static publishability protection for partially cleaned Xiumi v5 animation style picker residue.
- The live CloakBrowser DOM readback showed 50 occurrences of `anim-expand-bottom` inside animation
  style picker items whose parent `anim-style` text included effects such as fade-in, zoom fade-in,
  move-in, wipe-in, elastic zoom, and rotate-in.
- The committed rule covers the isolated `anim-expand-bottom` child so a copied icon/expand marker
  remains publish-blocking even when the broader `anim-style`, `anim-styles`, `anim-desc`,
  `anim-icon`, `animate-styles-type`, and `animate-general` parents have already been cleaned.

Implemented:
- Extended the existing `Xiumi animation style picker residue` detector to include
  `anim-expand-bottom`.
- Added a reduced fixture with only `<span class="anim-expand-bottom"></span>` and ordinary text.
- Kept the label shared with the animation style picker rule because this marker is an icon child
  of the same Xiumi editor-side style picker, not a separate article feature.

Regression coverage:
- WeChat, Xiaohongshu, and Zhihu all report the exact market-editor residue label.
- The reduced fixture does not rely on animation list markers, animation panel child markers,
  animation attribute panel markers, animate operation panels, Angular runtime attributes, hosted
  media, sidebar controls, or meta panels.
- The detector remains anchored to class/id markers and does not block ordinary animation wording,
  CSS animation properties, SVG `<animate>` elements, or motion-related article prose by itself.

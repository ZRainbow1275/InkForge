# 渲染结果为空专项修复

## Goal

在真实 InkForge Tauri/WebView2 软件中消除“已选择排版预设，但平台预览近似无渲染”的问题，使用户在工作台内立即看到与所选预设一致、可辨识、可复制到微信公众号的真实排版结果。

## Confirmed Facts

- 2026-07-28 已在当前交付软件、同一篇真实本地文稿、同一微信 Stage 中逐个切换全部 16 个现有预设并完成视觉取证。
- `赤陶旗舰`、`赤陶兼容旗舰`、`铜绿旗舰`、`黄铜旗舰`均能显示封面、部分 SVG 结尾模块与品牌色，证明文稿加载、微信 Stage、基础 HTML 注入和 SVG 显示链路并未整体失效；但 2026-07-28 用户最新软件截图同时证明其正文段落仍近似裸文本，不能把“出现封面/SVG”误判为完整渲染。
- `论文翻译`、`法学研讨`、`行业研报`、`时事点评`、`AIGC`、`编程创造`、`学习笔记`、`新闻`、`整活`、`人生感悟`、`优雅`、`科技`共 12 个普通预设，在同一位置仅显示近似裸文本；其 Inspector 虽声明了不同 `visualSignature`，Stage 中却没有呈现这些签名。
- `usePreviewRenderer()` 会在微信预览路径调用所选预设的 `decorate(..., 'preview')`，随后将 `generateThemeCSS(preset, 'preview')` 交给 `renderWechatMockHtml()`。
- `renderWechatMockHtml()` 已声明把 `#nice` 重写为 `#wechat-article` 并注入 `<style>`，因此 CSS 预览本来应当生效。
- 普通预设的大量装饰函数对 `target === 'preview'` 直接返回原 HTML，而旗舰装饰链会在本地预览中生成真实模块；这是目前最强的共享根因线索，但仍需在实施前通过调用链、产物 DOM 和影响分析确认。
- 最新真实软件截图还暴露了第二个独立可见缺陷：自动结尾的“墨铸”SVG 在移动宽度 Stage 中异常放大并被视口裁切，外层响应式宽度、模块自身 `viewBox`/纵横比、自动插入条件与宿主溢出规则必须一起核验。
- 最新截图中的测试正文只有普通段落，旗舰装饰器仅生成封面、作者/结尾等结构，正文没有形成可辨识的段落节奏、首段、分隔和主题表面；普通段落也必须成为预设视觉语言的一部分，而不能要求用户先手写内部 marker 才看到排版。
- 当前交付包的视觉结果是本专项的基线；历史单元测试、旧截图或浏览器预览不能替代本次真实软件验收。

## Requirements

- 本专项只处理“排版预设在平台预览中近似无渲染”这一条，不扩展到首页、设置、悬浮窗、专注模式、同步或发布等其他问题。
- 12 个普通预设全部升级到与旗舰预设相同的完整度，同时保持各自独特的视觉语言；只恢复基础 CSS 不算完成。
- 采用“结构自动生成，内容绝不编造”：封面、真实阅读时间、满足章节阈值的目录、预设结尾可以自动生成；标题、引用、分隔、列表、表格、图片等只转换已有正文语义。
- 时间线、对比卡、数据统计卡、图集、引文来源、歌曲、名片、文章链接、微信原生媒体组件，以及数字、来源、作者、图片和平台信息，必须提供用户可主动调用的生成或插入选项，不能只依赖用户手写内部 marker。
- 在编辑器光标位置提供与 doocs/md 同类的“组件库”入口，并同时接入现有斜杠命令；打开后保留插入位置，关闭或插入后焦点正确返回文稿。
- 组件库包含“内置组件”和“自定义组件”两个页签。内置组件至少覆盖公众号名片、作者卡、二维码、提示框、信息网格、表格、时间线、对比卡、数据统计卡、图集、引文来源、歌曲、图片、链接、关联文章、联系人/名片和可受支持的微信媒体描述。
- 每个组件声明稳定 ID、名称、说明、版本、类型化属性、必填项、默认值和平台能力；展开组件后可填写真实字段、即时预览、校验必填项，并在当前光标处插入。
- 自定义组件支持新建、编辑、删除、导入和导出，但只允许声明式模板与受限属性，不允许执行任意 JavaScript、事件处理器、脚本、iframe 或未经净化的外部代码。
- Typora 与源码模式必须共享同一组件注册表：可视模式显示可选中、可重新编辑的组件块；源码模式显示可读、可复制、可往返的 JSX 风格组件语法，并提供组件名/属性补全。
- 组件在文稿中保存语义和真实字段，而非提前固化为某一套样式 HTML；预览与导出时由当前预设渲染同一组件，使 16 个预设都能呈现各自视觉语言。
- 平台适配必须显式区分本地预览、通用兼容 HTML 和平台原生输出。微信公众号支持且经过验证的组件可输出平台识别标记；其余平台或缺少真实标识时输出安全降级卡片或待绑定状态，不伪造原生成功。
- 生成入口必须产出可编辑的真实结构；缺少真实字段时保持待填写/待绑定状态，不得把示例值、猜测值或平台占位符写入最终预览、复制、导出或发布产物。
- 修复共享根因，不在 12 个预设、3 个平台或多个预览表面重复添加临时补丁。
- 复用现有 `themePresets`、`visualSignature`、装饰器、SVG 模块库、预览管线和导出管线；不新增第二套渲染引擎或新依赖。
- 非空正文必须渲染当前真实文稿；空正文必须使用当前预设的真实样稿并标识为示例内容，禁止无解释白屏。
- 预设切换后，Stage、分栏预览和预览模式必须同步显示当前选择；旧异步结果不得覆盖新选择。
- 本地保真预览与微信复制/导出继续共享同一预设规则，但不得把仅供本地浏览器显示的 CSS 伪元素冒充为微信最终可用产物。
- 保持现有安全净化、平台隔离、复制/导出权威管线和全部已有功能、模块、组件不变。
- 最终视觉验收必须在真实 Tauri/WebView2 软件和本次新构建交付包中完成。

## Acceptance Criteria

- [ ] 16 个微信预设在真实 Tauri 工作台中都显示可见、非零尺寸且与其 `visualSignature` 一致的排版，不再有 12 个预设退化为裸文本的现象。
- [ ] 每个普通预设至少在标题、正文节奏、引用、分隔或结尾模块中呈现其独有识别点；不得仅复制同一旗舰模板后换色。
- [ ] 4 个现有旗舰预设的封面、SVG、结尾模块和品牌色不回退。
- [ ] 微信预览中的 `[data-platform-editor="wechat"]` 可见且尺寸非零；需要 SVG 的预设中，`[data-ink-svg]` 宽高均大于 0 且不溢出画布。
- [ ] Stage、分栏预览和预览模式对同一文稿、平台、预设给出一致结果。
- [ ] 空正文显示带“示例内容”标识的当前预设样稿；非空正文不被样稿替换。
- [ ] 时间线、对比卡、数据统计卡、图集和引文来源均有可发现的生成入口，生成后可继续编辑，且由当前预设实时渲染。
- [ ] 歌曲、图片、链接、关联文章、名片和微信原生媒体组件均有可发现的插入/配置入口；缺少真实 URL、账号、素材或平台标识时明确显示待补充，不写入假组件。
- [ ] “组件库”可从斜杠命令和编辑器插入入口打开；内置/自定义页签、展开属性、即时预览、必填校验、光标插入、关闭后焦点恢复均可真实操作。
- [ ] 内置组件与用户自定义组件使用同一注册、渲染和安全净化管线；自定义模板无法执行脚本、事件处理器、iframe 或任意运行时代码。
- [ ] Typora 组件块和源码 JSX 可双向往返；切换模式、自动保存、关闭重开文稿后组件 ID、版本、属性和插入顺序不丢失。
- [ ] 同一个组件在 16 个微信预设下使用各自视觉 token 和模块规则渲染，且微信复制/导出不携带仅供本地编辑器使用的控制 UI。
- [ ] 公众号名片等平台组件只有在真实平台字段完整时才进入平台原生输出分支；缺失字段和未经验证的原生能力均不能被标记为已完成。
- [ ] 微信复制/导出仍使用现有权威导出管线，相关结果保留预设签名且通过平台兼容性检查。
- [ ] 与共享渲染链相关的单元/组件回归、lint、类型检查和生产构建全部通过。
- [ ] 真实 Tauri/WebView2 E2E 逐个验证 16 个预设的可见性、非零尺寸和关键签名，并留存本次构建的视觉证据。
- [ ] 新交付包从本次已验证的前端产物构建，启动后重新完成同一轮真实软件复测。

## Out of Scope

- 知乎和小红书真实账号发布测试；由用户手动完成。
- 微信同步、定时发送、正式发布成功和手机端扫码预览。
- 用户此前列出的首页、设置、悬浮窗口、暗处聚焦、打字机模式、同步配置和发布中心布局问题。

## Confirmed Decisions

- 2026-07-28：用户选择“按推荐完整升级”。12 个普通预设必须达到旗舰级完整度，同时保持各自独特视觉语言，不能以恢复基础 CSS 作为本专项终点。
- 2026-07-28：用户采用“结构自动生成，内容绝不编造”，并要求所有高级内容模块和平台媒体组件都必须有可主动调用的生成选项。
- 2026-07-28：用户明确采用 doocs/md 在线编辑器的组件库交互作为目标：光标处打开组件库，提供内置/自定义组件、属性填写、即时预览、插入，以及自定义组件的新建/导入/导出能力。
- 2026-07-28：用户确认采用推荐架构。TipTap/Typora 可视模式使用类型化原子组件节点；Markdown 持久化、源码编辑、导入与导出使用 JSX 风格组件语法；两者必须无损往返并共享同一注册表。

Xiumi Interaction Style Residue - 2026-06-25

Scope:
- Convert the 2026-06-25 Xiumi applied SVG/style DOM readback into one additional static
  publishability blocker.
- No runtime browser state, screenshot, platform URL, account label, auth secret, QR payload, HAR
  payload, raw template source, media URL, save action, preview action, upload action, sync
  action, or publish action is recorded here.

Observed source:
- The sanitized Xiumi applied editor readback listed inline interaction style flags including
  `touch-action`, `user-select`, `position`, `display`, `width`, `vertical-align`, `overflow`,
  `flex-flow`, `justify-content`, `transform`, `visibility`, and `pointer-events`.
- Existing rules already blocked invisible/custom hit areas such as `visibility:hidden` and
  `pointer-events`, and WeChat-specific unsupported CSS catches several layout constructs.
- A cleaned fragment that retained only the interaction pair `touch-action` plus `user-select`
  remained worth blocking independently because it is editor interaction-layer state, not
  InkForge-owned publishable article styling.

Implemented:
- Added a `MARKET_EDITOR_RESIDUE_RULES` entry labeled `Xiumi interaction style residue`.
- The rule requires `touch-action` and `user-select` to appear in the same style attribute, avoiding
  a broad single-property block.
- Added a reduced regression fixture with only that style pair and readable text, intentionally
  without `tn-*`, `ng-*`, `opera-*`, `contenteditable`, hosted-media, SVG content-layer,
  `pointer-events`, `visibility:hidden`, or `foreignObject` markers.

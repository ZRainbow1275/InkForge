# 微信公众号真实粘贴渲染验收

## Goal

在用户已登录并主动打开的微信公众号文章编辑器中，使用 release `InkForge.exe`
真实执行“复制微信富文本”与普通系统 `Ctrl+V`，验证当前 16 个微信排版预设经过
微信 PC 编辑器粘贴清洗后的实际结构、样式、SVG 和可读性。

本轮还必须消除编辑页与渲染页的视觉割裂：编辑画布继续保持可编辑性，但必须从同一
canonical preset / variant / typography 状态获得可识别的字体、强调色、标题、引用和写作
组件语义，不能一侧长期显示通用粉色骨架、另一侧显示完全无关的成品版式。

发现缺陷时，只修复现有 InkForge 微信渲染、复制或兼容链的共享根因，重新构建
release 软件并在同一真实编辑器中复验。

## Confirmed Facts

1. 本机 release `InkForge.exe` 已能生成 16 个可选微信预设。
2. 本机 WebView2 预览不能证明微信公众号编辑器会保留相同 HTML、内联样式或 SVG。
3. 用户已经登录微信公众号并明确授权在当前编辑台粘贴测试内容。
4. 普通 OS `Ctrl+V` 是本轮唯一可计为 `pc-editor-paste` 的输入动作；程序化
   `ClipboardEvent` 只可用于诊断，不能冒充普通粘贴。
5. 微信 PC 编辑器验收不等于手机预览、Dark Mode、交互 SVG、封面、同步、群发或发布。

## Requirements

### R1. 真实应用到真实编辑器

- 富文本必须由当前 release `InkForge.exe` 的现有复制按钮产生。
- 微信平台交互只使用当前任务的既有 CloakBrowser 登录会话，不打开 Playwright、
  Chrome 或第二个浏览器 profile。
- 使用普通系统剪贴板和真实 `Ctrl+V` 粘贴到微信正文编辑区。
- 不用手工拼接 HTML、开发者工具写 DOM、程序化 paste event 或 mock 页面作为成功证据。

### R2. 逐套验证当前 16 个预设

对同一篇真实验收稿逐一验证全部 16 个微信预设，至少记录：

- 粘贴前 InkForge 预设 ID、可见名称和产物摘要；
- 粘贴后微信正文首屏的 masthead、H1/H2、第一段和整体宽度；
- 微信读回的正文非空、关键文本完整、inline style 数、SVG 数和 `data-ink-*` 哨兵；
- 正文、H1/H2/H3、引用和组件的实际字号、行高、字距与字体族，避免 CJK 正文被等宽字体、
  过大字号或过宽字距破坏阅读密度；
- 是否发生纯文本降级、样式丢失、SVG 丢失、固定宽度、溢出、重叠、浅底浅字或异常空白；
- 16 套在微信编辑器内仍保留品牌锚点，同时具有可识别的不同结构。

代表预设还需滚动检查标题层级、列表、引用、表格、代码、图片/题注、写作组件和文末
CC/colophon；不能只看首屏。

### R3. 安全、真实和可清理

- 仅操作用户当前明确提供的测试编辑台，不点击群发、发布、定时、同步或预览到手机。
- 每套测试前替换当前测试正文，避免把 16 套内容叠加到一个稿件；不改标题、封面、作者、
  摘要和账号配置，除非它们是当前测试稿中已存在的字段。
- 不记录或提交 Cookie、Token、二维码、账号截图、HAR、浏览器 profile 或本机临时路径。
- 临时视觉截图只保存在系统临时目录；文档仅记录脱敏结构指标和结论。

### R4. 缺陷修复边界

- 先确认缺陷发生在 InkForge 产物、普通剪贴板通道还是微信 sanitizer。
- 修复优先落在现有共享渲染/后处理/复制根因，不给 16 个预设逐一打补丁。
- 不新增第二套 renderer、依赖、store、数据字段或浏览器专用输出。
- 不删除、重命名或隐藏任何现有预设、SVG 模块、组件或平台功能。
- 修改符号前必须运行 GitNexus upstream impact；HIGH/CRITICAL 时先报告。

### R5. 编辑页与渲染页同源对应

- 编辑画布复用现有 preset/variant/settings 数据流，不新增第二套 renderer、theme store 或
  测试专用状态。
- 切换预设后，编辑画布的视觉语义、预览可见签名和导出 preset ID 必须一致。
- 写作组件在编辑过程中必须作为清晰的原子组件卡片出现，展示真实组件类型、已有字段摘要
  与错误状态；不能只留下不可辨识源码，也不能生成示例数据补空。
- “对应”不要求在 ProseMirror 中复制完整 masthead DOM；要求品牌和版式语义可辨、正文可读、
  编辑焦点/暗处聚焦/打字机/快捷键不回归。

## Acceptance Criteria

当前状态：用户最新视觉反馈重新打开的 AC-2–AC-9 已由当前 release 的 16 套原生视觉复验和
16 套微信 PC 普通粘贴矩阵重新闭合；历史结构矩阵仍只作为基线，不替代本轮证据。

- [x] AC-1：release `InkForge.exe` 和已登录微信公众号编辑台均可达。
- [x] AC-2：16/16 预设均通过真实复制按钮与普通 OS `Ctrl+V` 进入微信正文编辑器。
- [x] AC-3：每套粘贴后正文非空、关键验收文本完整，不出现未声明的纯文本降级。
- [x] AC-4：12 个基础预设与 4 个旗舰在微信编辑器中保留可识别的不同首屏结构。
- [x] AC-5：共同品牌锚点保留，但任意两套不退化为只换颜色的同一骨架。
- [x] AC-6：代表预设的中段、写作组件和文末无溢出、重叠、浅底浅字或异常大空白。
- [x] AC-7：静态 SVG/装饰按各预设预期保留；任何被微信剥离的 SVG 均被如实记录并有
  可读 HTML fallback，不能虚报保留。
- [x] AC-8：若发现产品缺陷，目标测试、export 串行回归、ESLint、类型检查、生产构建和
  Tauri release 构建通过，且修复后在微信编辑器复验通过。
- [x] AC-9：验收记录不包含账号身份、Cookie、Token、二维码、HAR、profile 或截图路径。
- [x] AC-10：不执行或声称手机预览、Dark Mode、交互触发、同步、定时、群发或发布成功。
- [x] AC-11：原生软件切换预设时，编辑画布、预览和导出使用同一 preset/variant；代表预设的
  标题、引用与真实写作组件在编辑态可识别，且编辑、焦点和打字机能力不回归。

## Out of Scope

- 小红书、知乎编辑器或发布测试；
- 微信手机端预览、Dark Mode、封面缩略图和交互 SVG 触发；
- 公众号授权同步、定时发送、群发和发布；
- 新增预设、写作组件、数据模型或第二套渲染器；
- 复制 135、秀米或其他第三方编辑器的 DOM、素材或私有样式。

## Constraints

- 保护当前大量 unrelated dirty changes，只精确修改本任务确认的文件。
- 控制内存；浏览器、release 软件、构建和重测不做重型并行。
- 不 stage、commit 或 push，除非用户后续明确批准提交计划。

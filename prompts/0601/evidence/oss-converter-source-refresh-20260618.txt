Findings:
- doocs/md and mdnice converge on the same WeChat converter pattern:
  theme CSS is collected, scoped or de-scoped for the export fragment, inlined with juice, then
  normalized for platform paste behavior before the HTML is copied or exported.
- doocs/md explicitly handles WeChat image width/height by converting raw image dimensions into
  inline style values, strips unresolved preview placeholders, removes local anchor hrefs, inserts
  boundary empty nodes, and applies SVG text compatibility fixes for tspan fill and diagram text
  baseline handling.
- doocs/md separates preview/share theme injection from clipboard/export content. Theme injection
  and exported CSS are workflow aids; the publishable clipboard artifact still needs inline,
  fragment-matching styles.
- mdnice keeps WeChat and Zhihu sidebar actions as separate copy workflows. WeChat math keeps SVG
  dimensions as style-level data, while Zhihu math is degraded to source formula text before copy.
- mdnice exposes theme and custom-style editing, but that custom CSS is an authoring source. It is
  not proof that arbitrary CSS survives a target platform; it still goes through converter logic.
- RedBookCards is aligned with Xiaohongshu-style output: Markdown becomes HTML pages, local images
  are normalized for the renderer, page breaks are explicit, and export captures fixed-size
  1080x1440 image pages from a real WebView render.

Rules added to project docs/specs:
- WeChat-style rich output must remain fragment-safe: source-owned CSS may be authored and themed,
  but export must resolve unsupported variables/calc where needed and inline the effective style
  into the copied HTML fragment.
- Clipboard/export readiness is not platform proof. A local copied HTML artifact does not satisfy
  authenticated PC editor paste, phone preview, Dark Mode, cover thumbnail, sync, schedule, or
  publish gates.
- Image dimensions should be normalized as inline style rather than relying on raw width/height
  attributes when targeting WeChat-like editors.
- Math, Mermaid, and SVG-derived diagrams require explicit platform shims or degradation. WeChat
  may preserve selected SVG shapes after exact proof, but Zhihu/XHS should receive semantic
  Markdown, formula text, public-host image, poster, or long-image fallback.
- XHS visual output should be treated as image-page or long-image artifacts with manifest
  validation, page count, dimensions, crop/cover consistency, and real file evidence.
- Zhihu and XHS workflows must stay separate from WeChat clipboard HTML; do not reuse WeChat
  wrappers, market editor residues, or inline SVG assumptions as publishable output for them.

Style Proof JSON Intake BOM Compatibility - 2026-07-03

Scope:
- Compatibility fix for redacted StyleProofManifest JSON packs authored on Windows or in editors
  that may write a leading UTF-8 BOM.
- No platform action, no phone preview, no sync, no upload, no schedule, no publish.

Implemented:
- getStyleProofManifestJsonIntakeReport(jsonText) now strips leading U+FEFF characters before
  size checks, empty checks, and JSON.parse().

Behavior:
- Valid BOM-prefixed JSON now reaches normal schema and semantic validation.
- BOM-only or whitespace/BOM-only input remains schema-invalid.
- Malformed JSON after BOM removal still returns style-proof-manifest-intake-json-invalid.
- Oversized checks apply to the normalized JSON text after leading BOM removal.
- No manifest schema, semantic proof, sensitive-artifact, freshness, cannot-claim, release-gate,
  upload, sync, schedule, or publish logic was relaxed.

Regression coverage:
- Export-service JSON intake accepts a BOM-prefixed valid manifest pack.
- Manifest-intake CLI accepts a BOM-prefixed temp JSON file and exits by cannot-claim state, not
  parse failure.

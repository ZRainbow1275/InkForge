## O. 文档生命周期与状态机

## L1-41 | 文档是否需要正式的生命周期状态
文档从创建到归档，是否需要正式的状态标记？

| 选项 | 描述 |
|------|------|
| A | 不需要正式状态 -- 文档只有"存在"和"删除"两态 |
| B | 轻量状态 -- 草稿/已完成/已归档 三态，仅作为标签无强制约束 |
| C | 正式状态机 -- 草稿 > 写作中 > 待审阅 > 待发布 > 已发布 > 归档，状态迁移有条件 |
| D | C + 不同状态下编辑权限不同（如"已发布"文档再编辑需显式"创建修订版"） |

**你的选择**: _C__
**补充**: _状态必须显示在文件管理器和 Hub 卡片上，可以进行过滤筛选__

## L1-42 | 文档的软删除与回收站策略
用户删除文档后，系统应如何保护数据安全？

| 选项 | 描述 |
|------|------|
| A | 硬删除 -- 删除即永久，无回收站 |
| B | 回收站 -- 删除后进入回收站，手动清空前可恢复 |
| C | B + 自动过期（回收站内 30 天后自动清理） |
| D | C + 删除前强制确认 + 删除操作写入审计日志 |

**你的选择**: __D_
**补充**: __回收站必须要在应用内部可以使用，可以占用存储统计，必须与版本历史关联_

## L1-43 | 文档收藏/置顶/固定能力

| B | 支持收藏/星标 -- 收藏文档在文件管理器置顶 |
| C | B + 支持固定到 Hub 首页 |
| D | C + 支持自定义"快速访问"列表，可排序、可分组 |

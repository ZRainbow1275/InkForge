## 一、系统架构概览

### 1.1 架构定位

InkForge 采用**分层架构**设计，遵循以下核心原则：

| 原则 | 描述 |
|------|------|
| **离线优先** | 所有数据存储在 IndexedDB，无需网络即可工作 |
| **单向数据流** | 视图层 → 状态层 → 服务层 → 存储层 |
| **关注点分离** | UI 组件、业务逻辑、数据持久化完全解耦 |
| **可测试性** | Repository 抽象层便于单元测试 |

## 二、核心模块设计

### 2.1 渲染管线（Rendering Pipeline）

参考 [doocs/md](https://github.com/doocs/md) 的四层管线架构：

```mermaid
graph LR
    A["Markdown 源码"] --> B["marked 解析"]
    B --> C0["DOMPurify XSS防护"]
    C0 --> C1["代码高亮(7主题)"]
    C1 --> C2["Alert块渲染"]
    C2 --> C3["外链转脚注"]
    C3 --> C["主题CSS注入"]
    C --> D["juice CSS内联"]
    D --> D1["表格增强"]
    D1 --> E["后处理补丁"]
    E --> F["平台适配"]
    F --> G["微信/小红书/知乎 HTML"]
```

#### 2.1.1 各层职责

| 层级 | 职责 | 实现位置 |
|------|------|----------|
| **XSS 防护** | HTML 消毒清理 | `DOMPurify` (`export/wechat.ts`) |
| **代码高亮** | 语法着色 + 行号 + Mac代码块 + 语言标签 | `highlight.js` + `export/utils.ts` |
| **Alert 块渲染** | GitHub 风格 `[!NOTE]` 等提示块 | `export/utils.ts` |
| **外链处理** | 微信:转脚注 / 小红书:剥离 / 知乎:学术引用 | 各平台导出文件 |
| **主题注入** | 将主题 CSS 注入 HTML | `export/themes.ts` → `generateThemeCSS` |
| **CSS 内联** | 将 `<style>` 转为 inline style | `juice` 库 |
| **表格增强** | 条纹行、圆角容器、主色表头 | `export/utils.ts` |
| **后处理补丁** | 平台兼容性修复（blockquote/figcaption/SVG/嵌套列表） | 各平台导出文件 |
| **平台适配** | 根据目标平台调整输出（微信/小红书/知乎） | `export/index.ts` → `convertToPlatform` |

#### 2.1.2 微信兼容性处理

> **核心约束**：微信公众号编辑器剥离所有 `<style>` 和 `<link>` 标签

| 处理项 | 方法 | 代码位置 |
|--------|------|----------|
| XSS 防护 | `DOMPurify.sanitize()` | `export/wechat.ts` |
| 代码高亮 | `highlight.js` class → inline style（7主题） | `export/utils.ts` |
| Alert 块 | `[!NOTE]` 等转 styled section | `export/utils.ts` |
| CSS 内联 | `juice(html, { inlinePseudoElements: true })` | `export/wechat.ts` |
| CSS 变量替换 | 正则替换 `var(--color)` → 具体值 | `export/wechat.ts` |
| 图片属性转样式 | `width="100"` → `style="width: 100px"` | `export/wechat.ts` |
| 嵌套列表修复 | `li > ul` 移为兄弟元素 | `export/wechat.ts` |
| 外链转脚注 | 非微信链接变底部引用 | `export/wechat.ts` |
| 表格增强 | 条纹行 + 圆角 + 主色表头 | `export/utils.ts` |
| blockquote 增强 | 左色条 + 浅灰背景 + 圆角 | `export/wechat.ts` |
| figcaption 样式 | 居中、斜体、灰色 | `export/wechat.ts` |

### 2.2 状态管理（State Management）

采用 **Pinia** + **FSM (有限状态机)** 模式管理复杂状态：

```typescript
// editor.ts - 状态机定义
type EditorStatus = 'idle' | 'loading' | 'ready' | 'saving' | 'error'

// 状态转换规则
idle → loading (选中文章)
loading → ready (加载成功)
loading → error (加载失败)
ready → saving (自动保存)
saving → ready (保存成功)
saving → error (保存失败)
```

#### Store 职责矩阵

| Store | 职责 | 持久化 |
|-------|------|--------|
| `editor.ts` | 编辑器生命周期、当前内容 | ❌ |
| `theme.ts` | 主题预设、CSS 生成 | ✅ localStorage |
| `article.ts` | 资讯列表、选中状态 | ✅ IndexedDB |
| `category.ts` | 分类管理 | ✅ IndexedDB |
| `ai.ts` | AI 配置、调用状态 | ✅ localStorage |

### 2.3 数据持久化（Repository Pattern）

采用 **Repository 抽象层** 解耦 Store 与 IndexedDB：

```typescript
// repository.ts - 接口定义
export interface IRepository<T, ID = string> {
    findAll(): Promise<T[]>
    findById(id: ID): Promise<T | undefined>
    create(entity: T): Promise<void>
    update(id: ID, updates: Partial<T>): Promise<void>
    delete(id: ID): Promise<void>
}

// 单例实例
export const categoryRepository = new CategoryRepositoryImpl()
export const articleRepository = new ArticleRepositoryImpl()
export const contentRepository = new ContentRepositoryImpl()
```

#### IndexedDB Schema

```typescript
// utils/db.ts
db.version(1).stores({
    categories: '++id, name, createdAt',
    articles: '++id, categoryId, sourceUrl, status, createdAt',
    contents: '++id, articleId',
    versions: '++id, contentId, createdAt'
})
```

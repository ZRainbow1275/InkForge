# Current Code Audit for R-01..R-23

## Scope and method

- Audited the live Vue/Tauri application under `inkforge/`; the legacy root source trees are not implementation targets.
- Traced visible UI entry points to current Pinia state, composables, export services, persistence, and Tauri commands.
- Treated existing tests and catalogs as evidence of capability, not proof that the present UI is coherent or that external platforms accepted an artifact.
- No product code was changed during this audit.

## Shared root causes

1. **Two desktop chrome layers**: `App.vue` always renders `TitleBar`, while `WorkstationView.vue` renders a second branded header and places focus controls without using the native title-bar safe area.
2. **Docked and transient panels share one width model**: the inspector animates between `12px` and its full flex-column width, so a hover reveal changes the editor layout instead of overlaying it.
3. **Three style and typography authorities**: export presets and platform renderers are mature, while `stores/theme.ts`, `ThemePanel.vue`, `ThemesView.vue`, and duplicated `appearance.fontSize/lineHeight` controls maintain parallel preview state.
4. **Artifact generation, proof diagnostics, and publishing share the same surface**: `ExportModal.vue` owns local export, style proof reports, WeChat draft creation, and diagnostics; `PublishView.vue` independently renders and copies again.
5. **Route identity is coupled to settings query state**: `ViewTransition.vue` keys all non-workstation routes by `route.fullPath`; every `?tab=` change destroys and recreates the entire settings shell.

## Canonical boundaries selected for design

- **Desktop shell**: global `TitleBar` owns app identity and native safe areas.
- **Workstation layout**: transient overlays do not change document geometry; docked panels do.
- **Style choices**: `services/export` presets plus `style-catalog.ts` are authoritative.
- **Typography**: `settings.appearance.typography` is authoritative; old scalar fields are migration aliases only.
- **Preview/export**: all visible previews use the platform renderer that produces the corresponding artifact family.
- **Delivery**: rendering produces an artifact snapshot; Export and Publish are separate consumers.
- **External proof**: local tests never claim phone preview, authenticated upload, sync, or publication success.

## Main implementation risks

1. `WorkstationView.vue` and `ExportModal.vue` are large and dirty-prone; changes must be sliced by shared state boundary and reviewed after every slice.
2. Removing duplicate UI must not remove data operations, command-palette actions, keyboard shortcuts, proof diagnostics, or migrations.
3. Old persisted theme, file-manager, and settings values require deterministic migration and rollback tests.
4. Tauri utility windows and folder writes require native-runtime tests; web mode must fail closed with an actionable message.
5. XHS/Zhihu technical editor limits are not publicly documented as a stable official whitelist; they must remain configurable/manual rather than encoded as permanent platform facts.

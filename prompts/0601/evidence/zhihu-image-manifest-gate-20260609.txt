Scope:

- Implement runtime preflight for Zhihu image fallback artifacts.
- Artifact kinds: inline image, formula image, diagram image, table image, cover.
- Boundary: local/platform-host readiness only. This file does not prove Zhihu account upload,
  editor preview, sync, scheduled publish, or final publish success.

Regression coverage:

- Bad manifest:
  - blocked `data:` image source,
  - `requirePlatformUpload:true` host violation,
  - platform-hosted artifact without `uploaded:true`,
  - missing local file proof,
  - missing alt,
  - formula/diagram semantic fallback without caption/text fallback,
  - unsupported format,
  - invalid dimensions,
  - invalid bytes,
  - final Markdown / manifest reference mismatch.
- Good manifest:
  - one platform-hosted diagram artifact,
  - `uploaded:true`,
  - positive dimensions,
  - allowed format,
  - non-empty alt and caption,
  - final Markdown image reference matches manifest.

Proof boundary:

- `artifacts.zhihuImageArtifactManifest` means local/platform-host preflight only.
- It is not a substitute for a real Zhihu upload response, editor DOM readback, preview result,
  sync result, scheduled publish proof, or final publish URL.
- Public HTTPS may satisfy local Markdown host readiness when `requirePlatformUpload` is false.
  Platform-hosted readiness requires `hostStatus:'platform-hosted'` plus `uploaded:true`.

Sensitive artifact hygiene:

- No browser profile path, cookie, token, QR code, account id, HAR, platform screenshot path, or
  authenticated page source is stored in this evidence file.

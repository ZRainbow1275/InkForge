Style Proof Manifest Intake CLI - 2026-07-03

Scope:
- Local, read-only intake and audit command for caller-supplied redacted StyleProofManifest JSON
  packs.
- No browser launch, upload, sync, scheduled send, publish, phone preview, clipboard write,
  committed manifest mutation, or proof artifact creation is performed by this CLI.

Implemented:
- Added package script:
  pnpm -C inkforge style-proof:manifest-intake --file <redacted-manifest.json>
- Added script:
  inkforge/scripts/style-proof-manifest-intake.ts
- Added regression suite:
  inkforge/scripts/style-proof-manifest-intake.test.ts
- Reused the existing intake service:
  getStyleProofManifestJsonIntakeReport()

Behavior:
- Reads a local UTF-8 JSON file from --file.
- Default output is sanitized text; --text is explicit default.
- --json prints a sanitized JSON summary.
- --help exits 0.
- Missing --file, unreadable files, unknown arguments, and conflicting --text/--json modes exit 2
  before claiming proof state.
- Malformed JSON produces a schema-invalid sanitized report and exits 2.
- Parsed but incomplete or cannot-claim proof exits 1.
- A supplied manifest pack can exit 0 only when the existing intake, acceptance audit, and
  execution runbook report canClaimComplete=true.

Sanitized output includes:
- source=file
- status
- canClaimComplete
- exitCode
- intake summary counts
- schema issue-id counts
- semantic issue-id counts
- per-platform requirement summaries
- cannot-claim rows by platform, requirement id, gate, status, issue ids, and counters

Sensitive material policy:
- The command does not print the input path.
- The command does not print raw manifest bodies or raw artifact references.
- Regression fixtures include a redacted private-reference-like artifactRef and assert it never
  appears in text or JSON output.
- Committed evidence records only sanitized command behavior, counts, row ids, issue ids, and
  proof requirements.
- No browser profile path, cookie, token, HAR, QR payload, account screenshot, local screenshot
  path, raw account-state capture, private material URL, sync response, upload response, draft id,
  scheduled-send id, or publish URL is included.

Xiumi UI Bootstrap Control Directive Residue - 2026-06-26

Scope:
- Static publishability protection for copied or partially cleaned Xiumi Angular UI Bootstrap
  control directives.
- Covers Xiumi UI Bootstrap directive attributes such as uib-dropdown, uib-dropdown-toggle,
  uib-dropdown-menu, uib-tooltip, tooltip-placement, and tooltip-popup-delay.
- No platform save, sync, copy-to-WeChat, preview, upload, scheduled send, or publish action.

Live source:
- CloakBrowser opened the live Xiumi v5 paper editor and read back top operation, authorization,
  message, statistics, and template-menu DOM.
- The editor DOM exposed uib-dropdown, uib-dropdown-toggle, uib-dropdown-menu, uib-tooltip,
  tooltip-placement, and tooltip-popup-delay on authoring controls.
- These directives drive editor dropdowns, tooltips, accordions, tabs, and menus. They are not
  article content, style, SVG payload, or platform-safe export markup.

Implemented:
- Added a reduced regression fixture that keeps only UI Bootstrap dropdown/tooltip directives
  after top operation classes, Angular ng-* attributes/classes, operator, paper auxiliary tree,
  selection overlay, crop/worker, hosted media, and interaction markers have been removed.
- Added the detector label:
  Xiumi UI Bootstrap control directive residue

Why this matters:
- Existing Xiumi guards already catch full Angular controls through ng-* attributes/classes and
  catch Xiumi operation buttons through op-btn/op-more classes.
- This slice covers the child-only path where copied DOM keeps uib-* or tooltip directives after
  broader classes and Angular markers have been cleaned.
- The rule intentionally does not match generic is-open or on-toggle attributes by themselves.

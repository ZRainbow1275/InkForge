# 微信公众号多主题编辑器 PRD v2.0

> **项目代号**：InkForge（墨铸）
> **基于**：doocs/md 二次开发
> **目标**：打造一款融合 Markdown 简洁美学、苏联现实主义与现代设计的微信公众号排版编辑器

---

## 一、微信公众号文章结构

> [!IMPORTANT]
> **核心认知**：微信公众号文章的结构是分离的，编辑器只负责**正文**部分。

### 1.1 微信文章组成

| 元素 | 填写位置 | 编辑器职责 |
|------|----------|------------|
| **封面图** | 微信后台上传 | ❌ 不负责 |
| **标题** | 微信后台填写（最多64字） | ❌ 不负责 |
| **摘要** | 微信后台填写（最多120字） | ❌ 不负责 |
| **作者** | 微信后台设置 | ❌ 不负责 |
| **正文** | 粘贴 HTML 富文本 | ✅ **核心职责** |

### 1.2 正文排版原则

由于标题由微信平台提供：
- **H1 不使用**：正文中不需要 H1 标题
- **H2 起始**：正文章节从 H2 开始
- **H3-H6**：用于子章节层级

## 二、项目背景与愿景

### 2.1 用户画像

- **身份**：半程序员内容创作者
- **内容类型**：10种不同风格的文章
- **美学追求**：Markdown 简洁 + 苏联现实主义 + 现代高级感
- **技术能力**：熟悉 HTML/CSS/Markdown，追求代码驱动的排版

### 2.2 核心痛点

| 痛点 | 描述 |
|------|------|
| 🎨 主题不统一 | 每类文章需要独特风格，手动调整耗时 |
| 📱 适配困难 | 微信对 CSS 限制多，调试成本高 |
| ⏱️ 排版耗时 | 希望内容优先，减少排版时间 |
| 🔗 知识孤岛 | 文章间缺乏关联，难以形成知识体系 |

### 2.3 设计哲学

```
内容第一 → 阅读第一 → 简洁高级 → 人文科技融合
```

## 三、技术架构（基于 doocs/md）

### 3.1 二次开发策略

**不从零开始**，而是基于 doocs/md 成熟框架进行扩展：

```
doocs/md (基础)
    ├── Markdown 解析引擎 (marked) ✅ 复用
    ├── CSS 内联引擎 (juice) ✅ 复用
    ├── 后处理补丁 ✅ 复用
    ├── 主题系统 → 扩展（从3个扩展到10+）
    ├── 配置选项 ✅ 复用并扩展
    └── 新增功能
        ├── 文章分类管理
        ├── 主题预设切换
        └── 知识关联标签
```

### 3.2 doocs/md 核心能力复用

| 能力 | 实现文件 | 复用策略 |
|------|----------|----------|

## 四、10种文章类型与主题预设

### 4.1 主题架构调整

**原设计**：10个完全独立的 CSS 主题
**新设计**：基础主题 + 参数化配置预设

```
基础主题 (3个)
    ├── default (经典)
    ├── grace (优雅)
    └── simple (简洁)

文章类型预设 (10个)
    └── 每个预设 = 基础主题 + 特定参数组合

        ├── 字体
        ├── 代码块主题
```

## 八、CSS 主题规范

### 8.1 微信兼容性要求

| 要求 | 规范 |
|------|------|
| ❌ 禁用 CSS 变量 | 构建时替换为具体值 |
| ❌ 禁用 @media | 不使用媒体查询 |
| ⚠️ 伪元素 | 需特殊处理 |
| ✅ 简单选择器 | 使用元素、类、ID |
| ✅ 内联样式 | 最终由 juice 内联 |

### 8.2 排版规范

| 属性 | 规范值 | 说明 |
|------|--------|------|
| 字体大小 | 15px | 每行约25字 |
| 行高 | 1.75-1.8 | 充足的呼吸感 |
| 字间距 | 0.03-0.05em | 阅读舒适度 |
| 段落间距 | 1.5em | 段落间留白 |
| 首行缩进 | 2em（可选） | 中文排版传统 |

### 8.3 正文结构（无 H1）

```markdown
## 章节标题（H2）

正文段落...

### 子章节（H3）

正文段落...

> 引用块

- 列表项

```代码块```
```

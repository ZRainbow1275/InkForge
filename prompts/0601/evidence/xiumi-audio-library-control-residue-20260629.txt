Xiumi Audio Library Control Residue - 2026-06-29

Scope:
- Local static publishability protection for copied or partially cleaned Xiumi v5 paper-editor
  audio/video library media-control chrome.
- No platform action, no phone preview, no sync, no upload, no publish.

Live DOM source:
- CloakBrowser read the live Xiumi v5 paper editor DOM at the logged-in paper editor surface.
- The sampled DOM exposed a hidden editor-side media control:
  <audio id="audio-library-control" class="bgm-audio ng-scope ng-hide" controls>
- Its ancestors place it inside the Xiumi audio/video library panel, adjacent to system music,
  personal music/video, upload music, and upload video controls.
- This element is editor chrome. It is not article body DOM, a platform-safe media embed,
  an upload manifest, a published audio proof, or a target-platform playback proof.

Implemented:
- Added `Xiumi audio library control residue` to `MARKET_EDITOR_RESIDUE_RULES`.
- The rule matches only an `<audio>` element carrying the exact `id="audio-library-control"`
  marker.
- The rule is ordered after hidden media upload input handling and before audio-panel chrome, so
  upload inputs, the hidden media control, and visible audio panel controls remain independently
  attributable.
- Added three-platform regression coverage for WeChat, Xiaohongshu, and Zhihu.

Negative scope:
- The rule does not block ordinary `<audio>` elements.
- The rule does not block ordinary prose about audio, music, video, media, background music,
  preview, controls, upload, or library wording by itself.
- The rule does not block `class="bgm-audio"` without the live Xiumi id.
- The reduced fixture does not rely on parent `audios` wrappers, audio panel controls, hidden
  upload inputs, generated-link controls, account/sync panels, Angular runtime attributes, hosted
  media, sidebar controls, or meta panels.

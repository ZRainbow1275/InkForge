R-05 First-Paragraph Indent Specificity Fix - 2026-07-23

Scope
- Local WeChat typography override behavior only.
- No foreground input, clipboard mutation, browser/account operation, sync, upload, or publish action.

Root cause
- Several presets, including thesis, own a more-specific `#nice p:first-of-type` rule.
- The former user override used only `#nice p`, so the preset could keep the first ordinary paragraph at `0` while later paragraphs used `2em`.
- The former generic paragraph override also allowed paragraphs inside blockquotes to inherit body indentation.

Pre-fix executable readback
- Thesis fixture: first ordinary paragraph `0`, second ordinary paragraph `2em`.
- Across all 16 canonical WeChat presets: first ordinary paragraph indented in 13/16; second ordinary paragraph indented in 16/16.
- Quote paragraphs could receive `2em`, so the existing broad assertion was not sufficient proof of body-paragraph behavior.

Shared-root repair
- `typographyToWechatCss()` now emits one specificity-matched body rule:
  `#nice p, #nice p:first-of-type { text-indent: <0|2em>; }`
- It immediately emits the quote boundary:
  `#nice blockquote p, #nice blockquote p:first-of-type { text-indent: 0; }`
- `convertToWechatWithStats()` uses the same selector pair whenever `enableTextIndent` is explicitly supplied.
- No new state, renderer, preset, dependency, or platform adapter was added.

Post-fix all-preset readback
- Indent ON: first ordinary paragraph 16/16 at `2em`; second ordinary paragraph 16/16 at `2em`; quote paragraph 16/16 unindented.
- Indent OFF: first ordinary paragraph 16/16 unindented; second ordinary paragraph 16/16 unindented; quote paragraph 16/16 unindented.

# 恢复渲染规范、检查器归位与写作组件插入

## Goal

在真实 InkForge Tauri 软件中恢复既定的移动端文章排版规范，把检查器放回正确的信息架构位置，清除编辑器操作面的英文残留，并让结构化组件在写作光标处即可发现、配置、预览、插入和继续编辑。

## Confirmed Facts

- 当前真实软件截图显示“检查器”以大面积覆盖层展开，并与排版预设、统计卡混在同一视觉区域；实际实现集中在 `inkforge/src/views/WorkstationView.vue` 的 `panel-inspector`、磁吸、停靠、应用内浮动与桌面小组件链。
- 旧任务 `.trellis/tasks/07-22-workbench-rendering-software-ux/prd.md` 要求检查器、平台预览、引用链接和文稿统计具有明确的停靠/浮动/桌面小窗边界，未停靠面板不得覆盖 Stage 控件。
- 生产 Tauri 的 inline-style CSP 根因已经修复；真实 WebView2 已测得 16/16 预设 CSSOM 生效、16 个独特签名和有界 SVG。当前问题不是再次修 CSP，而是恢复并完善原定文章结构与写作入口。
- 既定移动正文合同散见于 `prompts/0526/mobile-typography-chars/prd.md`、`prompts/0601/SPEC.md`、归档任务 `05-23-preset-typography-overhaul` 和 `06-01-multiplatform-render-svg`：375px 移动画布、16–17px 正文、约 1.6–1.8 行高、`max-width: 22em` 与约 20–22 个 CJK 字/行。
- `.trellis/spec/frontend/flagship-element-catalog.md` 已定义封面、阅读条、首字下沉、目录、H2、H3、引用/提示/金句、无序/有序列表、强调查亮、图片框、分隔线、数据卡和文末落款的顺序、安全规则及幂等哨兵。
- `prompts/0327/04-rendering-engine-spec.md` 与 `prompts/0420/specs/04-spec-rendering-core.md` 还要求标题 H1–H6、粗体、斜体、删除线、行内代码、代码块、KaTeX 公式、Mermaid、引用、列表、任务列表、表格、图片、链接和分隔线在编辑、预览、复制与导出之间保持语义一致并按平台安全降级。
- `inkforge/src/components/editor/EditorContextMenu.vue` 仍硬编码 `Cut`、`Copy`、`Paste`、`Bold`、`Italic`、`Strike`、`Inline code`、`Link`、`Image`、`Table`、`Divider`、`Find / Replace`、`Selection chars`、`Open in window`，与软件中文界面不一致。
- 当前 `DeliveryAdornmentPanel.vue` 只挂载于 `ExportModal.vue` 与 `PublishView.vue`；编辑器内不存在该入口。现有 `SlashCommands.ts` 只有基础标题、块、列表、图片、链接等命令，没有“组件库”命令。
- 旧任务 `.trellis/tasks/07-28-rendering-empty-output-fix/` 已确认 doocs/md 式组件方案：同一注册表、内置/自定义页签、类型化属性、即时预览、光标插入、TipTap 原子组件节点与 Markdown JSX 无损往返；该任务的组件注册、NodeView 和编辑器 UI 切片仍为 open。

## Requirements

### R-01 检查器信息架构

- 按原始工作台设计，检查器归属最右侧独立栏：默认可收成窄轨，展开后占用自己的栏宽，不覆盖正在编辑的正文、平台预览或预设选择。
- 停靠、收起、应用内浮动、桌面小窗和重新打开必须共享同一内容状态，并保留现有动画、持久化和无障碍能力。
- 现有小组件仍可从最右独立栏摘出为应用内浮动或桌面小窗，并能回到原栏位；不得删除检查器、平台预览、引用链接、文稿统计或已有浮动能力。

### R-02 文章抬头与移动正文基线

- 微信文章在 375px 移动画布的默认正文行长为约 22–24 个 CJK 字；不同预设可以在不低于 22 字的前提下调整字号、字距、行高和段间距，不得以大字号和巨大留白破坏阅读密度。
- 抬头形成完整编辑出版结构：可选真实歌曲组件、装裱/标题母题、右侧小字“文章值得您享受”、左下真实阅读时间、右下真实文章类别，然后进入正文。
- 歌曲、类别、作者、来源、图片和数字不得编造。用户未选择真实歌曲或文章没有真实分类时，最终平台产物不输出假数据或假原生组件。
- 抬头、正文、结尾均由当前预设 token/装饰规则生成；16 个预设保留各自独特视觉签名，不复制同一模板只换色。

### R-03 全 Markdown 元素排版

- 16 个微信预设必须为 H1–H6、正文首段与普通段落、粗体、斜体、删除线、行内代码、代码块、KaTeX 行内/块公式、Mermaid、引用、提示、金句、无序/有序/任务列表、表格、图片与题注、链接、分隔线、脚注/来源和文末信息提供完整规则。
- 每个预设至少在标题体系、正文节奏、引用/卡片、列表/表格、代码/公式、图片/分隔或首尾模块中的三个维度呈现独特、可解释的差异。
- 编辑预览、Stage、分栏、全屏、微信复制和导出共享语义与主题规则；仅平台不支持的构造走明确、安全的静态或图片降级。
- 继续遵守微信安全 SVG/HTML 子集、幂等装饰、无第三方编辑器残留、无 Emoji 图标和无伪平台成功状态。

### R-04 编辑器中文化

- 编辑器右键菜单、组件库、斜杠菜单及本轮新增提示全部使用中文产品文案；快捷键、代码语言、URL、Markdown/JSX 标识符保持原始技术形式。
- 不为这一组固定中文文案引入新的 i18n 依赖或第二套文案系统；若仓库已有可用消息注册表则复用。

### R-05 写作态组件库

- 在工作台渲染台（Stage）提供一个明确可见的“组件”入口，并增加 `/组件` 斜杠命令；两者打开同一组件库并保存当前编辑器选择位置。
- 从渲染台打开组件库时，预览区继续展示当前真实文稿；组件即时预览在库内显示，确认插入后写入此前保存的正文光标位置并恢复编辑焦点。
- 组件库按已确认方案提供“内置组件”和“自定义组件”页签、搜索、属性表单、必填校验、即时预览、插入、重新编辑、导入和导出。
- 内置组件至少覆盖作者/公众号名片、二维码、提示、信息网格、表格、时间线、对比卡、数据统计卡、图集、引文来源、歌曲、图片、链接、关联文章、联系人/名片和当前真实支持的微信媒体描述。
- 组件写入当前文稿语义而非只写发布尾部配置；同一组件随当前预设渲染。TipTap/Typora 显示可选择的组件块，Source 模式使用可读、可复制、可往返的 JSX 风格语法。
- 复用现有 `delivery-adornments`、`html-blocks`、SVG 模块、`BlockBoundaryInsertion` 和导出管线，不新增第二套渲染引擎或依赖。
- 缺少真实字段时组件停留在可编辑的“待补充/待绑定”状态；最终复制、导出和发布产物不得包含示例值、脚本、事件处理器、iframe 或未经净化的任意 HTML。

## Acceptance Criteria

- [x] 检查器在用户确认的位置工作；展开、收起、浮动、桌面小窗、关闭和重开均不遮挡主写作/预览操作，状态与动画连续。
- [x] 375px 微信移动画布的典型中文正文逐行实测落在约 22–24 字范围，16 个预设无横向溢出。
- [x] 抬头按真实数据呈现可选歌曲、装裱/标题母题、“文章值得您享受”、阅读时间和文章类别；缺失数据不生成假内容。
- [x] 同一全元素验收稿在 16 个预设下逐项覆盖 H1–H6、段落、强弱强调、列表、表格、代码、公式、Mermaid、引用、图片、链接、来源与结尾，且每个预设至少有三个可辨识差异维度。
- [x] `EditorContextMenu` 不再出现本轮列出的英文 UI 文案；所有命令仍执行原有真实操作。
- [x] 写作态有可见“组件”入口与斜杠命令；组件库可配置真实字段、即时预览并准确插入原光标位置。
- [x] 组件在 Typora/Source 切换、自动保存、关闭重开后保持 ID、版本、字段、位置与顺序；未知/旧版本组件可恢复而不丢原始语法。
- [x] 微信复制/导出不包含编辑器控制 UI、假数据、危险节点或 135/秀米残留；XHS/Zhihu 只验证本地安全降级，不执行真实发布。
- [x] 聚焦单元/组件测试、渲染回归、ESLint、`vue-tsc`、生产构建和真实 Tauri 软件视觉验收全部通过。

## Out of Scope

- 知乎、小红书和微信公众号的真实发布、同步、定时发送及账号内手机预览；用户自行完成外部发布测试。
- 删除或替换任何现有预设、模块、组件、文稿、素材、设置或历史记录。

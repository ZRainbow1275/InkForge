# 工作台渲染与软件化高定修复

## Goal

把 InkForge 从“浏览器页面式功能堆叠”收敛为具有明确桌面信息架构、稳定面板行为、统一组件语言和完整多平台渲染能力的创作软件；逐项修复用户在 25 张实机截图中指出的 23 个问题，同时保留每项仍有价值的真实业务能力，删除的仅是重复、失效或位置错误的入口与呈现。

## Background

- 本任务为独立 Trellis 系列任务，不与既有 `05-12`、`05-28` 任务混写。
- 用户当前重点验收工作台渲染功能，但范围同时覆盖工作台顶部、标签、检查器、文件栏、导出/发布、设置、关于页和首页。
- 25 张截图已经逐张审阅。截图直接证明：同一能力存在重复入口；部分面板在窄宽度、专注模式或常态展开时发生裁切、跳跃或控制不可见；多个渲染参数界面重复但只有一组真正生效；平台和内容类型样式目录与实际渲染能力脱节；部分设置仍暴露原生浏览器控件或内部诊断文本。
- 本任务不是一次整体换壳或重写。应先恢复原始产品信息架构和共享状态边界，再用现有 Vue/Tauri、设计 token、图标库、Store、持久化和导出管线完成最小共享根因修复。

## Confirmed Facts and Decisions

- 当前交付目标是 `inkforge/` 下的 Vue 3 + Tauri 1.6 桌面应用；根目录历史代码和 `prompts/0420` 只作为规划证据，不建立第二套实现。
- `App.vue` 的全局 `TitleBar` 是应用身份和原生安全区的唯一所有者；工作台内部只保留文档命令栏。
- `services/export/themes.ts`、XHS/Zhihu 平台预设、`style-catalog.ts` 和平台 renderer 是样式与渲染权威；旧 `stores/theme.ts` 只承担兼容映射。
- `settings.appearance.typography` 是排版参数唯一可写源；旧顶层字号/行高字段仅用于确定性迁移。
- 未停靠的右侧检查器使用覆盖层，不改变编辑器几何；只有用户明确停靠的面板占用持久化宽度。
- 渲染生成统一平台产物；导出负责本地复制/写盘，发布负责渠道、账号、草稿/同步/人工交接，两者不再共用同一动作页面。
- 微信公众号、小红书、知乎保持独立产物家族和规则。小红书、知乎的账号上传/正式发布由用户人工验收，本地测试不得替代或虚报。
- 历史规划明确存在标准 HTML、标准 Markdown 和配置式发布适配器，但仓库没有可执行的 WordPress/Ghost 远端协议。用户已确认本轮个人博客采用 Hugo/Hexo/Jekyll 兼容的静态站点内容目录，不追加未指定的远端 API。

## Requirements

### Workstation chrome and panels

- **R-01 顶部工作台工具组**：重新编排“文件、版本、大纲、标签、对话”等顶栏功能，使图标、文字、间距、激活态和收起入口形成稳定、整齐、可响应的桌面工具组，不再挤压或视觉失衡。（截图 1）
- **R-02 标签系统**：重排标签面板的信息层级、管理入口、文章标签、创建、全部标签和筛选区域；消除层层套卡、按钮裁切和与工作台视觉语言不一致的问题，但保留真实标签创建、筛选、管理和文章关联能力。（截图 2）
- **R-03 右侧自动展开**：恢复鼠标接近右侧时平滑展开渲染/检查面板的原始设计；展开和收起必须稳定，不得因 hover 边界、宽度切换或滚动条出现而跳跃。
- **R-04 审阅入口可达**：检查器常态展开、收起、自动展开和不同窗口宽度下，`审阅` 模式按钮始终可见、可聚焦、可点击，不被面板或溢出裁切。（截图 3）
- **R-05 排版参数单一事实源**：字号、行高、字间距、段间距、首行缩进、标题风格、引用样式及正文相关选项只保留一套真实控制；每一项都必须直接改变当前预览和导出产物，不允许存在重复但失效的滑块或选项。（截图 4）
- **R-06 暗处聚焦与打字机模式**：两个模式必须产生清晰、可感知、可撤销且不破坏编辑位置的真实效果；视觉强度和滚动定位应符合桌面写作软件预期。
- **R-07 可摘出检查器小组件**：检查器中的适用卡片可以从停靠区摘出为 InkForge 窗口内浮动组件，并在 Tauri 支持时作为独立桌面小窗存在；组件需支持移动、重新停靠、关闭、状态同步和窗口恢复。具体首批可摘出项由代码与原规划审阅后确定。
- **R-08 引用链接布局**：修复检查器底部“引用链接”区域的高度、内边距、空状态和滚动边界，所有说明和链接必须完整可读。（截图 5）
- **R-09 专注模式安全区**：专注模式内容、退出按钮和状态栏必须避开 Tauri 标题栏以及最小化、最大化、关闭控件；任何窗口尺寸下不得重叠。（截图 6）
- **R-10 品牌标识去重**：同一视觉层级只保留一个 InkForge 品牌标识；标题栏已有品牌时，工作台头部不得重复展示第二个图标，同时保留任务栏/应用窗口所需的原生图标。（截图 14）
- **R-11 文件栏信息架构**：默认且唯一主视图为树形文件结构；移除无价值的“平铺”和“最近”入口，消除“最近/快速访问/树节点”重复。左侧主区域按原计划展示固定文件夹内的文章与素材，并保留分类、状态、拖放、选择、右键操作和持久化关系。（截图 15、16）
- **R-12 分栏视图**：分栏按钮必须产生明确且稳定的编辑器/渲染预览双栏效果，支持可拖拽分隔、合理最小宽度、持久化布局和退出后的恢复；不得只有标签或无可见变化。（截图 17）

### Rendering, export, and publishing

- **R-13 渲染界面去重**：内容风格只在一个主选择区呈现；重复的渲染样式、质量检测、能力目录和内部证明文本不得占据主流程。具体参数放入靠近预览的可折叠高级设置窗口，内部诊断仅在明确的开发/诊断入口展示。（截图 7、8、9、10）
- **R-14 内容类型样式完整**：论文翻译、法学研讨、行业研报、时事点评、AIGC、编程创造、学习笔记、新闻、整活、人生感悟、优雅、科技等已有内容类型都必须对应真实可辨识的渲染配方，而非仅改变名称或底部色条。旗舰样式不是唯一真正生效的样式。（截图 11、12）
- **R-15 小红书与知乎样式**：为小红书和知乎建立各自真实平台样式目录、渲染规则和导出约束；规则来自官方/真实编辑器、当前平台实机观察和可核验资料，并记录到项目 docs/spec。不得把一套微信公众号样式仅换平台名称后复用。（截图 13）
- **R-16 导出与发布职责分离**：回溯原始规划，将“导出”恢复为本地文件/剪贴板/静态产物生成，将“发布”恢复为目标渠道选择、账号/权限、草稿/同步/发送状态和外部平台边界；两者共享渲染产物但不是同一页面或同一动作。
- **R-17 个人博客与本地文件夹渠道**：恢复原计划中的个人博客发布渠道和个人文件夹存储渠道；本轮真实写出标准 Markdown/HTML、frontmatter 和相对资产目录到用户选择的 Hugo/Hexo/Jekyll 兼容静态站点目录，并使用真实配置、路径边界、失败回滚和错误反馈，不以占位卡片或模拟成功交付。

### Settings and about

- **R-18 设置切换无黑屏**：外观、编辑器、导出等设置大类切换保持同一设置壳层，仅平滑切换内容和左侧激活指示；不得通过黑屏、整页闪烁或重建窗口完成。
- **R-19 设置控件统一**：所有按钮、文件选择、刷新、开关和操作行使用统一尺寸、间距、字体、圆角、焦点和禁用态；修复“刷新扩展”换行和原生 Manifest 文件输入等突兀控件。（截图 18、19）
- **R-20 关于页重排**：关于页在设置壳层内保持左侧导航可见，信息按品牌、版本/更新、运行时、数据与致谢分组，长技术信息可折叠或进入诊断详情；不得出现横向裁切、裸文本堆叠和操作按钮挤压。（截图 20、21）

### Hub

- **R-21 首页创建入口去重**：保留首页“开始”区域和右下角红色新建菜单；移除顶部加号及“最近编辑”卡片中的“空白草稿/从模板创建”重复入口，并强化“最近编辑”标题层级。所有被保留的创建、模板和导入能力仍可达。（截图 22、23）

- **R-23 首页搜索真实可用**：搜索栏必须查询真实文章数据，支持键盘快捷键、输入反馈、结果导航、无结果状态和清除；不能只是可聚焦的装饰输入框。（截图 25）

## Cross-cutting Constraints

- 不以新增第二套组件或第二套渲染状态解决重复问题；共享能力必须有单一事实源。
- 删除重复入口不等于删除底层功能；所有仍有产品价值的能力必须保留在一个明确的规范入口。
- 不引入 mock、占位内容或假发布结果。
- 不使用 Emoji 图标；复用当前安装的图标库和设计 token。
- 保留真实 Tauri 桌面边界、键盘可达性、焦点恢复、窄窗口适配、持久化和错误反馈。
- 不进行无证据的大规模重构；复杂耦合以真实调用链、GitNexus 影响面和测试证据分片修复。
- 小红书、知乎及第三方平台研究需要区分本地可验证规则与账号/外部发布人工边界。

## Acceptance Criteria

- [ ] `R-01` 至 `R-23` 每项都在任务验收矩阵中具有：截图证据、当前代码锚点、修改文件、目标测试、真实 UI 证据和最终状态。
- [ ] 工作台在标准桌面宽度、窄桌面宽度、检查器停靠/自动展开/浮动、专注模式和分栏模式下无按钮裁切、面板跳跃、标题栏重叠或横向溢出。
- [ ] 标签、文件树、检查器、设置和首页不再出现用户指出的重复入口；保留能力均可从唯一规范入口完成真实操作。
- [ ] 所有排版参数均通过同一状态模型驱动编辑预览和平台导出；参数逐项改变可通过确定性测试和真实界面检查证明。
- [ ] 每个内容类型渲染配方在同一真实文章输入上生成可区分、结构正确的产物；不得只有标签、名称或色条差异。
- [ ] 微信公众号、小红书和知乎各自具有独立规则与样式映射；已验证和外部人工边界在 UI、文档与报告中保持一致。
- [ ] 导出、发布、个人博客和本地文件夹形成职责清楚的真实流程，失败可见且不伪造外部成功。
- [ ] 个人文件夹/静态站点写入使用真实 Tauri 文件系统边界；成功后逐文件回读，失败时旧目标不被部分覆盖，Web 运行时明确不可用而非假成功。
- [ ] 设置大类切换没有黑屏或壳层重建；关于页和所有设置控件符合统一桌面组件规范。
- [ ] 首页搜索、每日来源切换/编辑及所有保留的创建入口使用真实 Store、持久化或 AI 服务，并在重启后保持应持久化的状态。
- [ ] 相关单元/组件测试、类型检查、lint、Tauri 构建和真实桌面 UI 验收通过；关键渲染与布局命题至少包含一个能在回归时失败的自动检查。
- [ ] 没有现有业务模块、数据或用户配置因本任务丢失；迁移与回滚边界记录在 `design.md`。

## Out of Scope

- 不在没有证据的情况下重写整个 Vue/Tauri 应用或替换现有编辑器框架。
- 不把小红书、知乎或微信公众号的账号登录、手机端预览和正式发布成功伪装成本地自动化完成。
- 不在未指定协议、认证方式和目标站点的情况下虚构 WordPress、Ghost 或其他远端个人博客 API。
- 不在本任务中引入与 23 项问题无关的新业务域。

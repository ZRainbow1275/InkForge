4. The strengthened native replay then exposed a test assumption: fuzzy search may render more than one command, so the first favorite is not necessarily the last focusable control. The harness now uses real Tab presses until the actual last visible favorite, then proves Tab/Shift+Tab wrapping.

7. Parallel Terser intermittently failed with `Cannot set property code of which has only a getter`. Minification remains enabled; `terserOptions.maxWorkers=1` produced repeated successful compressed builds within the local memory envelope.
8. Independent re-review found that capping Favorites at five could hide every later favorite because Recent/Featured correctly exclude favorite ids. The cap was removed and a seven-favorite overlap regression now requires every favorite to remain visible exactly once.
9. The same re-review required authoritative denial-side audit evidence. The unit regression now separates all-required semantics from runtime proof and asserts denied `auditLogged=false` with zero handler/audit calls; the native replay requires all three audit reads to return `ok=true`, requires a non-zero `command.execute` baseline from earlier successful commands, and then requires zero count delta after both click and Enter retry.

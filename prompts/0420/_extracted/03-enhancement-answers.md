# 第一章 第一层增强（L1-41 ~ L1-60，共 20 题）

## 本层核心决策摘要（5 条）

1. **文档拥有正式状态机**（L1-41=C）+ **软删除+回收站+过期+审计**（L1-42=D）+ **多层收藏分类**（L1-43=D）+ **归档可批量管理**（L1-44=D）—— 文档生命周期需要独立的 FSM 模块。
2. **写作目标走时间维度**（L1-45=C，带动画/奖励 + Hub 洞察）+ **专注模式深度做到退场总结**（L1-46=D，保留快捷键/斜杠/保存）+ **无独立阅读模式**（L1-47=A）。
3. **StatusBar 实时统计做到字/段/读时**（L1-48=B）+ **iA Writer 式安静界面 + 写作专用配色**（L1-49=B+C）。
4. **Tauri：多窗口 + 标签拖拽跨窗口**（L1-53=C）+ **文件系统深度集成（打开本地 + 监控文件夹 + 冲突检测）**（L1-54=D）+ **托盘 + 全局快捷键快速笔记**（L1-55=C）+ **更新仅通知不强推**（L1-56=B）。
5. **主题/字体全面可自定义**：中英文字体独立 + 开源优先（L1-57=D）、完整主题编辑器 + UI/内容区主题可分离（L1-58=D）、切换有分层过渡（L1-59=C）、Typography 全面可调（L1-60=D）。

## O. 文档生命周期与状态机

### L1-41 | 文档是否需要正式的生命周期状态

**问题概述**: 文档从创建到归档是否需要正式的状态标记。

**选项**:
- A: 不需要正式状态 -- 只有"存在"和"删除"
- B: 轻量状态 -- 草稿/已完成/已归档 三态，仅作标签无强制约束
- C: 正式状态机 -- 草稿 > 写作中 > 待审阅 > 待发布 > 已发布 > 归档，状态迁移有条件
- D: C + 不同状态下编辑权限不同（如"已发布"需显式"创建修订版"）

**用户选择**: C

**用户补充**: 状态必须显示在文件管理器和 Hub 卡片上，可以进行过滤筛选

**决策含义**: 需要一个正式的 6 态 FSM；状态是一等公民，必须出现在 FileManager 列表项和 Hub 卡片上，并接入过滤系统（F-03 的智能文件夹）。不需要做编辑权限控制（未选 D）。

**落点建议**: 新增 `DocumentLifecycle` Spec（状态机定义、UI 展示规范、过滤集成）；扩展 FileManager、Hub card-recent/card-featured、F-03 智能文件夹。

### L1-42 | 文档的软删除与回收站策略

**问题概述**: 用户删除文档后的数据保护策略。

**选项**:
- A: 硬删除
- B: 回收站 + 手动清空
- C: B + 自动过期（30 天）
- D: C + 删除强制确认 + 审计日志

**用户选择**: D

**用户补充**: 回收站必须要在应用内部可以使用，可以占用存储统计，必须与版本历史关联

**决策含义**: 完整的回收站体系：过期机制、删除确认、审计日志、容量统计、与版本历史联动；不能只是一个"trashed=true" 标记，需要专门的面板。

**落点建议**: 新增 `TrashCan / RecycleBin` Spec；与 `DataInsights`（存储统计）、`VersionHistory`、`activity-logger`（审计）联动。

### L1-43 | 文档收藏/置顶/固定能力

**问题概述**: 是否需要让用户标记"重要文档"。

**选项**:
- A: 不需要
- B: 收藏/星标 + 置顶
- C: B + 固定到 Hub 首页
- D: C + 自定义"快速访问"列表（可排序、可分组）

**用户选择**: D

**用户补充**: 收藏是分类的一种

**决策含义**: 收藏不做独立字段，而是"虚拟分类"的一种形态（与 F-01 的虚拟分类语义统一）；快速访问列表需要可排序、可分组；Hub 首页有专门的"Pinned"区域。

**落点建议**: 并入 `FileManager` Spec 的虚拟分类设计；Hub `card-pinned` 新增；与 L1-44 归档、F-01 嵌套分类一起组成"内容组织"子系统。

### L1-44 | 文档归档的语义

**问题概述**: "归档"与"删除"的差异。

**选项**:
- A: 不区分
- B: 归档 = 只读保留
- C: B + 归档不参与统计
- D: C + 归档可批量管理

**用户选择**: D

**用户补充**: 归档文档是过气的文档，可以留作做后续使用

**决策含义**: 归档是"冷存储"：只读、不出现在主列表、不进入写作统计、可批量导出/迁移/清理。需要与 DataInsights 的统计口径解耦。

**落点建议**: `DocumentLifecycle` Spec 的归档子章节；DataInsights 统计需过滤归档；FileManager 需提供"归档视图"。

# 第二章 F 文件管理与内容组织（F-01 ~ F-08）

## 本组核心决策摘要（5 条）

1. **分类为多层嵌套 + 虚拟分类**（F-01=D）+ **收藏/智能文件夹统一**（F-03=D、L1-43=D 呼应）。
2. **全量批量操作**（F-02=D）—— 移动、删除、导出、改标签、状态变更、归档全部批量化。

# 附录 A 关键矛盾与权衡点

## A.1 StatusBar 信息范围冲突

- **L1-48 B**：字数 + 字符数 + 段落数 + 阅读时长（不含行列号）
- **N-01 C**：B + 阅读时长 + 纸张宽度 + 目标进度（未提行列号但 B 选项含）
- **问题**：B 选项的"B"在 N-01 是 L1-48 的 C，两题字段集不完全一致
- **建议**：以 N-01 C 为准（阅读时长 + 纸张宽度 + 目标进度），明确**不显示行列号**

## A.2 右栏职责 vs 参考分屏

- **W-01 A**：右栏**仅预览**
- **W-06 D**：支持两篇文档并排对比
- **问题**：并排对比的副栏放哪里？如果放右栏，则 W-01 A 需放宽
- **建议**：引入"右栏模式切换器"（预览 / 参考文档 / 分屏对比），默认仅预览

## A.3 链接自动检测的取舍

- **E-02 D**：智能标点包含"自动链接检测"
- **E-08 C**：未选 D，即**不**做自动链接检测
- **问题**：E-02 把"自动链接"作为智能标点子项，E-08 D 独立出来并未选中
- **建议**：统一以 **E-08 C 为准（不做自动链接检测）**，或在 Settings 中"智能标点-自动链接"默认关闭

## A.4 iA Writer 哲学 vs 功能密度

- **L1-49 B+C**：写作氛围 + 写作配色
- **L1-52 A**：所有功能第一天可见
- **N-01 C + 补充**：StatusBar 功能丰富 **但可整体关闭**
- **N-06 D**：撤销按钮 Toast（功能密度高）
- **建议**：确立"默认极简，全开关可打开"原则；关键开关（StatusBar/iA 模式）走显著入口

- **但 0327 无 card-recent 组件**（仅命名）

## 整体矛盾清单（≤5 条）

1. **T09-04（每组件自定义空状态，A）vs T09-13（最严视觉一致性 D + 设计语汇映射）**：自由设计空状态与严格一致性审查之间存在张力；需在 design-language.md 中建立"空状态设计准则"约束自定义实现。

2. **X-05（Lighthouse>80 + 极致性能）vs T08-01+T08-03（6 个新图表 + 引入轻量图表库）vs T09-02（页面切换动画全套）**：大量新组件/新库/新动画会冲击 Lighthouse 分数；需通过 T09-09 自动降级 + T08-11 图表降级 + X-11 预计算 Web Worker 共同保证。

3. **T07-07（不做单独设置导出，随账户导出 B）vs X-09（文档版本包 D）vs S-15（账户/工作区隔离恢复 D）**：设置依附账户、版本依附文档、会话依附账户/工作区，三条数据绑定线交叉复杂；需在 PRD 数据模型章节统一定义 scope 树（Device → Account → Workspace → Document → Version）。

4. **X-10（批量操作 C，不要单独回滚每次批量）vs X-09（文档版本包 D 全量回滚）vs S-11（模板升级绝不反向污染已有文章）**：版本包全量回滚 + 命令自动生成版本点 + 模板不反向污染，三者在"版本粒度"上需要明确语义分层——文档版本是主线，命令版本点挂在文档版本下，模板版本独立不交叉。

5. **T07-02（Sync 走 Git D）vs X-04（DB 迁移脚本 B）vs X-11（灾难恢复 C，文章不能丢）**：Git 同步引入的 conflict/rebase 场景与 DB 迁移失败/损坏场景之间的交互未定义（Git 仓库里的 .md 与 IndexedDB 内数据的 source of truth 谁胜）；需补问或在 PRD 中明确"IndexedDB 为 primary，Git 为 derived"。
